## 一、项目概览

GoClaw 是一个**单二进制多功能 AI 代理网关**，核心功能：

- **Agent 运行时**：`internal/agent` + `internal/pipeline` — 8 阶段可插拔 pipeline
- **LLM 提供方**：`internal/providers` — Anthropic / OpenAI / Codex / ACP 等
- **工具体系**：`internal/tools` — 文件系统、Shell、网页、代理、MCP 桥接等
- **多渠道接入**：`internal/channels` — Telegram / Discord / Slack / WhatsApp / Zalo / Feishu 等
- **持久化**：PostgreSQL（pgvector）为主，SQLite（`sqliteonly` tag）为桌面版
- **双前端**：`ui/web`（Vite/React）嵌入式 SPA + `ui/desktop`（Wails）。**本文与 DreamWeaver 相关任务里若只写「前端」而无特别说明，均指 Web 端 `ui/web`**，不包含 Wails 桌面壳。
- **DreamWeaver 扩展**：记忆、压缩、Spirit 编排、插件市场、炼化、织梦坊

### 模块数量统计

| 层级 | 数量 |
|------|------|

## 三、安全性

### 3.1 认证与授权

| 级别 | 发现 | 详情 | 状态 |
|------|------|------|------|
| 🔴 严重 | **无 Gateway Token = HTTP Admin** | `internal/http/auth.go`：空 token 时 HTTP 获 `RoleAdmin` | 🟡 **行为未改**；✅ `InitGatewayToken("")` 时 **启动 `slog.Warn`**，提示非 localhost 须配置 token |
| 🔴 高 | **无 Gateway Token = WS Operator** | `internal/gateway/router.go`：空 token 时 WS 获 `RoleOperator` | 🟡 **行为未改**（与 HTTP 告警一并提醒运维） |
| 🟡 中 | **HTTP vs WS 角色不一致** | 无 token：HTTP→Admin, WS→Operator | 🟡 仍为产品语义差异；需长期统一或单独文档 |

**缓解**：`GOCLAW_GATEWAY_TOKEN` 必须在非 localhost 部署中设置。`.env` 已 gitignore。启动日志已对「空 token」与「空 AllowedOrigins」给出明确安全告警。

## 五、架构分层

### 5.1 包依赖合规

```
agent → tools       ✅（agent 调用 tools）
agent → pipeline    ✅（agent 构建 pipeline）
pipeline → tools    ❌ 不导入（通过回调）
pipeline → agent    ❌ 不导入（通过回调）
tools → agent       ❌ 不导入 ✅
tools → hooks       ✅（via context value）
http → agent        ✅（HTTP handler 调用 agent router）
gateway → agent     ✅（WS handler 调用 agent router）
```

**评估**：分层设计**严谨**，pipeline 通过 `PipelineDeps` 回调与 agent 解耦，tools 通过 context value 获取 hook fire 函数，避免了循环依赖。
