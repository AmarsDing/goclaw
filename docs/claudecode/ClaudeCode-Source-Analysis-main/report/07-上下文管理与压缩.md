## 7.1 三层压缩机制

```mermaid
flowchart TB
    subgraph L1 ["第一层：MicroCompact"]
        M1["触发：旧工具结果存在"]
        M2["操作：替换为 '[Old tool result content cleared]'"]
        M3["特点：不调用 API，本地编辑"]
        M4["效果：提示词主线完全保留"]
        M1 --> M2 --> M3 --> M4
    end

    subgraph L2 ["第二层：AutoCompact"]
        A1["触发：Token 消耗 ≥ 87%"]
        A2["操作：预留 13K 缓冲，生成 ≤ 20K 摘要"]
        A3["熔断器：连续 3 次失败停止"]
        A4["效果：显著压缩保留关键信息"]
        A1 --> A2 --> A3 --> A4
    end

    subgraph L3 ["第三层：Full Compact"]
        F1["触发：/compact 命令或系统判断"]
        F2["操作：AI 生成全对话摘要"]
        F3["前置：CRITICAL - 纯文本，禁止调工具"]
        F4["后处理：注入最近文件、计划、schema"]
        F5["预算：压缩后 ≤ 50K Token"]
        F1 --> F2 --> F3 --> F4 --> F5
    end

    START["Token 压力检测"] --> L1
    L1 -->|"不够"| L2
    L2 -->|"不够"| L3
```

## 7.2 记忆系统

**双模型协同检索**：调用快速 AI 模型（如 Claude Sonnet）扫描所有记忆文件标题和描述，选出最多 5 个最相关的记忆注入上下文。策略是"精确度优先于召回率"。

记忆层级：

```
~/.claude/MEMORY.md         ← 全局记忆
./.claude/memory/*.md       ← 项目级记忆
./.claude/sessions/*.json   ← 会话记录
```

早期版本使用 Voyage embeddings 的 RAG 方案已被放弃，替换为 ripgrep 代理式搜索。

## 7.3 autoDream / KAIROS 夜间记忆蒸馏

```mermaid
flowchart TB
    subgraph triggers ["触发条件（四项全部满足）"]
        T1["距上次整合 ≥ 24 小时"]
        T2["≥ 5 个新会话"]
        T3["无其他整合进程运行"]
        T4["距上次扫描 ≥ 10 分钟"]
    end

    triggers --> ORIENT["Phase 1: Orient<br/>读取 MEMORY.md，扫描记忆文件"]
    ORIENT --> GATHER["Phase 2: Gather<br/>检查日志，找出过时记忆"]
    GATHER --> CONSOLIDATE["Phase 3: Consolidate<br/>合并、更新、解决矛盾"]
    CONSOLIDATE --> PRUNE["Phase 4: Prune<br/>保持 MEMORY.md ≤ 200 行 / 25KB"]
```

AI 在低活跃期"睡觉"时，将原始日志蒸馏压缩成结构化的"用户偏好"和"项目背景"文件——仿生学意义上的记忆巩固。
