# 工具系统 (Tools)

## 功能概述

30+ 内置工具，供 Claude 在对话中调用：文件操作（读/写/编辑）、代码搜索（grep/glob）、Shell 执行（bash/powershell）、Web 能力（fetch/search）、子 Agent 管理、任务管理、MCP 工具、Notebook 编辑、计划模式、Worktree、TODO 管理、配置工具等。每个工具遵循统一接口：`name`、`inputSchema`、`call()`、权限检查、UI 渲染。

---

## 从 main 函数入口的实现流程

### 1. 工具注册

| 文件路径 | 关键函数 | 职责 |
|---------|---------|------|
| `src/Tool.ts` | `buildTool(def)` | 合并 `TOOL_DEFAULTS` 与工具定义，生成完整 Tool 对象 |
| `src/Tool.ts` | `toolMatchesName()`, `findToolByName()` | 工具名匹配和查找 |
| `src/tools.ts` | `getAllBaseTools()` | 返回所有内置 Tool 实例数组（含条件加载） |
| `src/tools.ts` | `getTools(permissionContext)` | 应用 deny 规则、simple 模式过滤后返回可用工具 |
| `src/tools.ts` | `assembleToolPool(permissionContext, mcpTools)` | 合并内置工具 + MCP 工具，去重排序 |
| `src/tools.ts` | `getMergedTools()` | 合并所有来源的工具 |

**注册流程**：`main.tsx` action 处理器 → `getTools(toolPermissionContext)` → `getAllBaseTools()` 导入所有工具 → 过滤 → 传入 REPL。

### 2. 工具接口（Tool 类型）

`src/Tool.ts` 中定义的核心接口：

| 字段 | 类型 | 职责 |
|------|------|------|
| `name` | `string` | 工具名称（API 中使用） |
| `description` | `string` | 工具描述 |
| `inputSchema` | `ToolInputJSONSchema \| (() => ...)` | JSON Schema 定义输入参数 |
| `prompt` | `string \| (() => string)` | 提供给模型的使用说明 |
| `call(args, context, canUseTool, parentMsg, onProgress?)` | `async function` | 工具执行逻辑 |
| `checkPermissions(args, context)` | `function` | 工具级权限检查 |
| `validateInput(args)` | `function` | 输入验证 |
| `isConcurrencySafe(args)` | `function` | 是否可并发执行 |
| `isReadOnly(args)` | `function` | 是否为只读操作 |
| `renderToolUseMessage(args)` | `React component` | 工具调用的 UI 渲染 |
| `renderToolResultMessage(result)` | `React component` | 工具结果的 UI 渲染 |
| `mapToolResultToToolResultBlockParam()` | `function` | 结果转换为 API 格式 |

### 4. 工具执行流程

| 文件路径 | 关键函数 | 职责 |
|---------|---------|------|
| `src/services/tools/toolOrchestration.ts` | `runTools()` | 主编排器：分区 → 并发/串行执行 |
| `src/services/tools/toolOrchestration.ts` | `partitionToolCalls()` | 按并发安全性分组工具调用 |
| `src/services/tools/toolOrchestration.ts` | `runToolsConcurrently()` | 并发批量执行（最多 10 并发） |
| `src/services/tools/toolOrchestration.ts` | `runToolsSerially()` | 串行执行 |
| `src/services/tools/StreamingToolExecutor.ts` | `StreamingToolExecutor` | 流式传输期间预执行工具 |
| `src/services/tools/StreamingToolExecutor.ts` | `.addTool()` | 流式接收时入队 |
| `src/services/tools/StreamingToolExecutor.ts` | `.getRemainingResults()` | 按顺序 yield 结果 |
| `src/services/tools/toolExecution.ts` | `runToolUse()` | 单工具执行：查找 → 验证 → Hook → 权限 → call() → 后处理 |

**`runToolUse()` 执行步骤**：
1. `findToolByName()` 查找工具定义
2. 缺失工具 → 别名回退
3. `validateInput()` 输入验证
4. PreToolUse Hooks 执行
5. `canUseTool()` 权限检查（可能弹出确认对话框）
6. `tool.call(args, context)` 实际执行
7. PostToolUse Hooks 执行
8. `mapToolResultToToolResultBlockParam()` 结果转换

## 工具执行流程图

```
API 返回 AssistantMessage (含 tool_use 块)
    │
    ▼
query.ts: 收集 toolUseBlocks
    │
    ├── (流式执行模式)
    │     StreamingToolExecutor.addTool(block)
    │       └── processQueue() → executeTool() → runToolUse()
    │
    └── (标准模式)
          runTools(toolUseBlocks, context)
            │
            ├── partitionToolCalls()
            │     ├── 并发安全组 → runToolsConcurrently() (max 10)
            │     └── 串行组 → runToolsSerially()
            │
            └── 每个工具 → runToolUse()
                  ├── findToolByName(name)
                  ├── validateInput(args)
                  ├── PreToolUse Hooks
                  ├── canUseTool() → 权限检查
                  │     ├── allow → 继续
                  │     ├── ask → 弹出确认对话框
                  │     └── deny → 返回错误
                  ├── tool.call(args, context)
                  ├── PostToolUse Hooks
                  └── mapToolResultToToolResultBlockParam()
                        │
                        ▼
                  创建 UserMessage (tool_result)
                  追加到 messages → 回到 queryLoop 下一次迭代
```
