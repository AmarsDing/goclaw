# Claude Code 核心调用链分析

> 本文档追踪 Claude Code 的**实际**核心流程：  
> **CLI 启动 → 用户在终端输入消息 → Agent 调用 Anthropic Messages API → 流式返回结果渲染到终端**

---

## 重要说明

本项目 **Open-ClaudeCode** 是 Anthropic 官方 Claude Code CLI 的源码复原版。它的核心流程**不是** "启动服务器 → Telegram 收消息 → 调用 OpenAI API"。实际上：

- **不是 HTTP 服务器**：它是一个交互式 CLI 程序，通过终端直接与用户交互
- **无 Telegram 集成**：代码中仅在注释里提到 Telegram 作为潜在的 MCP channel 插件，但无任何 Telegram bot 实现
- **不调用 OpenAI API**：使用 `@anthropic-ai/sdk` 调用 Anthropic Messages API（支持直连、AWS Bedrock、GCP Vertex、Azure Foundry）

---

## 完整调用链总览

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 阶段 1: CLI 启动                                                        │
│   cli.tsx  →  main.tsx  →  init.ts  →  replLauncher.tsx                │
│              (Commander 解析参数 → 初始化配置/认证 → 启动 REPL)           │
├─────────────────────────────────────────────────────────────────────────┤
│ 阶段 2: 用户输入处理                                                     │
│   REPL.tsx  →  handlePromptSubmit()  →  processUserInput()             │
│              (PromptInput 组件 → 输入校验/命令分发 → 构建消息)             │
├─────────────────────────────────────────────────────────────────────────┤
│ 阶段 3: Agent Query Loop                                               │
│   REPL.tsx:onQuery  →  query.ts:query()  →  queryLoop()               │
│              (准备系统提示/上下文 → 进入 while(true) 循环)                 │
├─────────────────────────────────────────────────────────────────────────┤
│ 阶段 4: 调用 Anthropic API                                              │
│   query/deps.ts  →  claude.ts:queryModelWithStreaming()                │
│              →  queryModel()  →  withRetry()  →  getAnthropicClient() │
│              →  anthropic.beta.messages.create({stream: true})         │
├─────────────────────────────────────────────────────────────────────────┤
│ 阶段 5: 流式响应处理 & 工具执行                                           │
│   claude.ts (for await stream)  →  query.ts (yield events)            │
│              →  REPL.tsx:onQueryEvent  →  handleMessageFromStream()    │
│              →  Messages 组件渲染到终端                                   │
│   如果响应包含 tool_use → runTools() 执行工具 → 结果追加到消息 → 循环回阶段4│
└─────────────────────────────────────────────────────────────────────────┘
```

## 阶段 3: Agent Query Loop

### 3.1 Query 入口

| 顺序 | 文件路径 | 关键函数 | 职责 |
|------|---------|---------|------|
| ① | `src/screens/REPL.tsx` | `onQuery()` → `onQueryImpl()` | REPL 层的 query 入口：准备 IDE 集成、工具权限上下文、会话标题生成 |
| ② | `src/screens/REPL.tsx` | `onQueryImpl()` 内部 | 构造 `QueryParams`，调用 `query()` 生成器，用 `for await` 消费 StreamEvent |

### 3.2 Query 核心循环

| 顺序 | 文件路径 | 关键函数 | 职责 |
|------|---------|---------|------|
| ③ | `src/query.ts` | `query()` | 顶层 async generator；委托给 `queryLoop()` 并管理命令生命周期通知 |
| ④ | `src/query.ts` | `queryLoop()` | **核心 Agent 循环**（`while(true)`）：每次迭代 = 一次 API 调用 + 工具执行；决定是否继续循环 |
| ⑤ | `src/query/deps.ts` | `productionDeps()` | 依赖注入：将 `queryModelWithStreaming` 绑定为 `deps.callModel` |
| ⑥ | `src/query/config.ts` | `buildQueryConfig()` | 构建不可变的查询配置（功能门控、实验标志等） |

### 3.3 queryLoop 每次迭代的步骤

```
queryLoop() — while(true) {
  1. 解构当前 state (messages, toolUseContext, autoCompactTracking...)
  2. yield { type: 'stream_request_start' }           // 通知 UI 开始新请求
  3. 构建完整系统提示 (systemPrompt + userContext + systemContext)
  4. 检查 token 限制 / 自动压缩
  5. ─── 调用 API (阶段 4) ───
     for await (message of deps.callModel({...})) {
       yield message                                  // 流式传递到 UI
       收集 assistantMessages, toolUseBlocks
     }
  6. ─── 工具执行 (如果有 tool_use) ───
     runTools(toolUseBlocks, toolUseContext)           // src/services/tools/toolOrchestration.ts
     收集 toolResults
  7. 判断是否继续:
     - 有 tool_results → continue (循环回步骤 1，带上工具结果)
     - stop_reason == 'end_turn' → return (结束)
     - stop_reason == 'max_tokens' → 恢复逻辑
     - 达到 maxTurns → return
}
```

## 阶段 4: 调用 Anthropic API

### 4.1 调用链

| 顺序 | 文件路径 | 关键函数 | 职责 |
|------|---------|---------|------|
| ① | `src/query/deps.ts` | `productionDeps().callModel` | 等价于 `queryModelWithStreaming`——依赖注入入口 |
| ② | `src/services/api/claude.ts` | `queryModelWithStreaming()` | 公开接口；包装 `queryModel()` 并添加 VCR 录制/回放能力 |
| ③ | `src/services/api/claude.ts` | `queryModel()` | **核心 API 调用函数**（~2,000 行）：构建请求参数、工具 schema、beta headers、缓存策略等 |
| ④ | `src/services/api/withRetry.ts` | `withRetry()` | 重试包装器：处理 429/529 限流、OAuth 刷新、streaming fallback、指数退避 |
| ⑤ | `src/services/api/client.ts` | `getAnthropicClient()` | 创建 `Anthropic` SDK 客户端实例；根据环境变量选择 provider (Direct/Bedrock/Vertex/Foundry) |
| ⑥ | `@anthropic-ai/sdk` | `anthropic.beta.messages.create({stream: true})` | **实际 HTTP 请求**：向 Anthropic API 发送流式请求 |

### 4.2 详细调用链

```
deps.callModel({messages, systemPrompt, tools, signal, options})
  │
  └── queryModelWithStreaming()          // src/services/api/claude.ts:752
        └── withStreamingVCR(messages, async function*() {
              yield* queryModel(messages, systemPrompt, thinkingConfig, tools, signal, options)
            })
              │
              └── queryModel()          // src/services/api/claude.ts:1017
                    ├── getMergedBetas(model)            // 构建 beta header 列表
                    ├── 工具过滤 & ToolSearch 处理
                    ├── 构建 paramsFromContext():
                    │     ├── buildSystemPromptBlocks()   // 系统提示 → API 格式
                    │     ├── toolToAPISchema()           // 工具 → API schema
                    │     ├── addCacheBreakpoints()       // 提示缓存标记
                    │     ├── getThinkingConfig()         // 思考模式配置
                    │     └── configureTaskBudgetParams() // token 预算
                    │
                    ├── withRetry(getClient, requestFn, retryOptions)
                    │     │                              // src/services/api/withRetry.ts
                    │     ├── getAnthropicClient({model, source, ...})
                    │     │     │                        // src/services/api/client.ts:88
                    │     │     ├── 根据环境变量判断 provider:
                    │     │     │     ├── ANTHROPIC_API_KEY → Direct API
                    │     │     │     ├── AWS Bedrock → AnthropicBedrock
                    │     │     │     ├── Vertex AI → AnthropicVertex
                    │     │     │     └── Foundry → Azure endpoint
                    │     │     └── return new Anthropic({apiKey, baseURL, ...})
                    │     │
                    │     └── requestFn(anthropic, attempt, context):
                    │           │
                    │           └── anthropic.beta.messages    ← ★ 实际 API 调用
                    │                 .create(
                    │                   { ...params, stream: true },
                    │                   { signal, headers }
                    │                 )
                    │                 .withResponse()
                    │                                    // 返回 Stream<BetaRawMessageStreamEvent>
                    │
                    └── for await (part of stream) {     // 消费流式响应
                          switch(part.type) {
                            case 'message_start' → 初始化 usage
                            case 'content_block_start' → 创建内容块 (text/thinking/tool_use)
                            case 'content_block_delta' → 累积增量内容
                            case 'content_block_stop' → 完成内容块
                            case 'message_delta' → 更新 stop_reason, usage
                            case 'message_stop' → yield 完整 AssistantMessage
                          }
                          yield StreamEvent (text_delta/thinking_delta/...)
                        }
```

### 4.3 API 请求参数结构

```typescript
{
  model: "claude-sonnet-4-6",           // 模型标识
  max_tokens: 16384,                     // 最大输出 token
  system: [...],                         // 系统提示块 (带缓存标记)
  messages: [...],                       // 对话历史 (user/assistant 交替)
  tools: [...],                          // 工具定义 (30+ 工具的 JSON Schema)
  stream: true,                          // 启用流式传输
  betas: ["interleaved-thinking-...",    // beta 特性头
          "prompt-caching-...", ...],
  metadata: { user_id: "..." },          // 用户/会话元数据
  thinking: { type: "enabled",           // 扩展思考配置
              budget_tokens: 10000 }
}
```

## 阶段 5: 流式响应处理 & 渲染

### 5.1 事件流传递链

| 顺序 | 文件路径 | 关键函数 | 职责 |
|------|---------|---------|------|
| ① | `src/services/api/claude.ts` | `queryModel()` 内 `for await` 循环 | 将 SDK 原始事件转换为 `StreamEvent` / `AssistantMessage` 并 yield |
| ② | `src/query.ts` | `queryLoop()` 内 `for await` 循环 | 接收 claude.ts yield 的事件，再次 yield 给调用者 |
| ③ | `src/screens/REPL.tsx` | `onQueryImpl()` 内 `for await` 循环 | 消费 query.ts 的事件流 |
| ④ | `src/screens/REPL.tsx` | `onQueryEvent()` | 回调函数；将事件传递给 `handleMessageFromStream()` |
| ⑤ | `src/utils/messages.ts` | `handleMessageFromStream()` | 事件分类处理器：text_delta → 更新文本、tool_use → 更新工具状态、完整消息 → 追加到 messages |
| ⑥ | `src/screens/REPL.tsx` | `setMessages()` | React state 更新，触发重渲染 |
| ⑦ | `src/components/Messages.tsx` | `<Messages>` | 渲染消息列表 |
| ⑧ | `src/components/Message.tsx` | `<Message>` | 渲染单条消息（文本、Markdown、代码块） |
| ⑨ | `src/components/Markdown.tsx` | `<Markdown>` | 终端 Markdown 渲染 |
| ⑩ | `src/ink/` (自研 Ink 框架) | `renderer.ts` / `render-node-to-output.ts` | React → ANSI 转换 → 终端输出 |

### 5.2 工具执行循环

当 API 返回 `tool_use` 内容块时，query loop 会执行工具并将结果反馈给 API：

```
queryLoop() 第 N 次迭代:
  API 返回 AssistantMessage 包含 tool_use 块
    │
    ├── StreamingToolExecutor 预执行            // 流式传输时并行执行
    │     └── src/services/tools/StreamingToolExecutor.ts
    │
    └── runTools(toolUseBlocks, toolUseContext)  // src/services/tools/toolOrchestration.ts
          ├── 权限检查 (canUseTool)
          │     └── src/hooks/toolPermission/handlers/interactiveHandler.ts
          ├── 执行对应 Tool:
          │     ├── BashTool      → spawn 子进程执行 shell 命令
          │     ├── FileReadTool  → 读取文件内容
          │     ├── FileEditTool  → 编辑文件 (diff 应用)
          │     ├── FileWriteTool → 写入文件
          │     ├── GrepTool      → ripgrep 搜索
          │     ├── GlobTool      → 文件名模式匹配
          │     ├── WebSearchTool → 网页搜索
          │     ├── AgentTool     → 启动子 Agent
          │     └── ... (30+ 工具)
          └── 构建 tool_result UserMessage
                │
                └── 追加到 messages → continue → 回到 queryLoop 步骤 1
                    (下一次迭代将 tool_result 发送给 API)
```
