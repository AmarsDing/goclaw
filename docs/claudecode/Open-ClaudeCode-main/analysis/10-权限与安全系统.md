# 权限与安全系统

## 功能概述

多层权限控制：权限模式（default/acceptEdits/bypassPermissions/plan/auto）、工具级权限检查（allow/deny/ask 规则）、交互式确认对话框、Hooks 拦截、分类器自动审批、Swarm 权限委托、沙箱隔离。确保 Claude 在执行文件操作和 Shell 命令前获得用户授权。

---

## 从 main 函数入口的实现流程

### 1. 权限模式定义

| 文件路径 | 关键导出 | 职责 |
|---------|---------|------|
| `src/types/permissions.ts` | `PermissionMode` | 权限模式联合类型 |
| `src/types/permissions.ts` | `PermissionBehavior` | `'allow' \| 'deny' \| 'ask'` |
| `src/types/permissions.ts` | `PermissionDecision` | 权限决策结果 |
| `src/types/permissions.ts` | `PermissionResult` | 完整权限结果（含原因） |
| `src/types/permissions.ts` | `ToolPermissionContext` | 运行时权限上下文 |
| `src/utils/permissions/PermissionMode.ts` | `permissionModeSchema` | Zod 验证 Schema |
| `src/utils/permissions/PermissionMode.ts` | `toExternalPermissionMode()` | 转换为外部模式名 |

**权限模式**：

| 模式 | 行为 |
|------|------|
| `default` | 每次危险操作弹出确认对话框 |
| `acceptEdits` | 自动接受文件编辑，其他操作仍需确认 |
| `bypassPermissions` | 跳过所有权限检查（⚠️ 仅限沙箱环境） |
| `plan` | 只读计划模式，禁止写操作 |
| `auto` | 基于分类器自动审批（实验性） |
| `dontAsk` | 不提问，遇到需要确认的操作直接拒绝 |

### 2. 权限检查管道

| 文件路径 | 关键函数 | 职责 |
|---------|---------|------|
| `src/utils/permissions/permissions.ts` | `hasPermissionsToUseTool()` | 主入口：`CanUseToolFn` 类型 |
| `src/utils/permissions/permissions.ts` | `hasPermissionsToUseToolInner()` | 内部实现：deny 规则 → ask 规则 → 工具级检查 |
| `src/utils/permissions/permissions.ts` | `checkRuleBasedPermissions()` | 基于规则的权限判定 |
| `src/utils/permissions/permissions.ts` | `getAllowRules()` | 获取允许规则 |
| `src/utils/permissions/permissions.ts` | `getDenyRuleForTool()` | 获取拒绝规则 |
| `src/utils/permissions/permissions.ts` | `toolAlwaysAllowedRule()` | 工具总是允许的规则 |

**检查流程**：
1. 检查 deny 规则 → 如果匹配则直接拒绝
2. 检查 always-allow 规则 → 如果匹配则直接允许
3. 调用 `tool.checkPermissions()` → 工具自定义权限逻辑
4. 根据权限模式决定：
   - `bypassPermissions` → 总是允许
   - `dontAsk` → `ask` 变为 `deny`
   - `auto` → 调用分类器
   - `default` → 返回 `ask`（需要用户确认）

### 3. UI 权限确认

| 文件路径 | 关键函数 | 职责 |
|---------|---------|------|
| `src/hooks/useCanUseTool.tsx` | `useCanUseTool()` | React Hook：将权限结果路由到对应处理器 |
| `src/hooks/toolPermission/handlers/interactiveHandler.ts` | `handleInteractivePermission()` | 交互模式：弹出 PermissionRequest 对话框 |
| `src/hooks/toolPermission/handlers/coordinatorHandler.ts` | `handleCoordinatorPermission()` | Coordinator 模式：hooks → 分类器 → 对话框 |
| `src/hooks/toolPermission/handlers/swarmWorkerHandler.ts` | `handleSwarmWorkerPermission()` | Swarm Worker：分类器 → 转发到 Leader |
| `src/hooks/toolPermission/PermissionContext.ts` | `createPermissionContext()` | 创建权限上下文（allow/deny/hooks/classifier/queue） |
| `src/hooks/toolPermission/PermissionContext.ts` | `createPermissionQueueOps()` | 创建权限队列操作 |
| `src/components/permissions/PermissionRequest.tsx` | `PermissionRequest` | 权限确认对话框组件 |

**交互式处理流程**（`interactiveHandler.ts`）：
1. 推入权限队列
2. 并发竞争：本地 UI 确认 / Bridge 远程确认 / Channel 渠道确认（Telegram/Discord） / Hooks 拦截 / 分类器自动
3. 首个响应获胜
4. 持久化允许规则（如果用户选择 "Always allow"）

### 4. 权限规则持久化

| 文件路径 | 关键函数 | 职责 |
|---------|---------|------|
| `src/utils/permissions/permissions.ts` | 规则持久化辅助 | 保存 always-allow 规则到配置 |
| `src/state/AppStateStore.ts` | `toolPermissionContext` 字段 | 运行时权限状态 |

**规则类型**：
- `alwaysAllowRules.session` — 会话级别自动允许
- `alwaysAllowRules.command` — 当前命令/Skill 附带的允许规则
- `alwaysAllowRules.config` — 用户配置的永久允许规则

### 5. 沙箱隔离

| 文件路径 | 关键导出 | 职责 |
|---------|---------|------|
| `src/utils/sandbox/` | 沙箱相关 | 沙箱环境检测和管理 |
| `src/utils/permissions/filesystem.ts` | `ensureScratchpadDir()`, `isScratchpadEnabled()` | 临时工作区隔离 |
| `src/entrypoints/sandboxTypes.ts` | 沙箱类型 | 沙箱模式类型定义 |

### 6. Hooks 权限拦截

| 文件路径 | 关键函数 | 职责 |
|---------|---------|------|

## 连接到 main.tsx 的流程

```
main.tsx action 处理器
    │
    ├── 解析 --permission-mode → PermissionMode
    ├── 解析 --dangerously-skip-permissions → bypassPermissions
    │
    ├── 构建 toolPermissionContext
    │     ├── mode: PermissionMode
    │     ├── alwaysAllowRules: {session: [], command: [], config: [...]}
    │     └── denyRules: [...]
    │
    ├── getTools(toolPermissionContext) → 过滤被 deny 的工具
    │
    └── REPL.tsx
          ├── useCanUseTool() → Hook 注入权限检查能力
          │     └── hasPermissionsToUseTool()
          │           ├── deny 规则检查
          │           ├── allow 规则检查
          │           ├── tool.checkPermissions()
          │           └── 模式分发:
          │                 ├── ask → handleInteractivePermission()
          │                 │         → <PermissionRequest> 对话框
          │                 ├── allow → 直接执行
          │                 └── deny → 拒绝并返回错误
          │
          └── 工具执行
                └── runToolUse() → canUseTool() → 上述流程
```
